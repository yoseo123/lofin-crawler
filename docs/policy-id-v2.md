# 중앙정부 정책 ID v2와 색인 전환

## 식별 기준

현재 `map_central_row()`가 보존하는 식별 후보는 회계연도, 소관명, 회계명,
프로그램명, 단위사업명, 세부사업명이다. 사업 코드나 상세팝업 토큰은 이 출력
계약에 없으므로 추정해서 쓰지 않는다. 향후 공식 코드가 원본부터 내보내기까지
보존된다면 별도의 ID 버전으로 검토한다.

중앙정부 ID는 출처, 버전, 회계연도, 지역, 자치단체, 위 5개 계층명을 JSON으로
직렬화한 값의 SHA-256 전체를 사용한다 (`central-v2-` 접두사).
구분자 문자가 이름에 들어가도 필드 경계가 충돌하지 않는다. 이름은 NFC와 공백
연속 축약을 적용한다. 내부 공백을 전부 삭제하거나 문장부호를 제거하지 않는다.
세부사업명이 없으면 기존 `사업명`을 사용한다. 제목 표시는 기존 동작을 유지한다.

모든 계층명이 있으면 `identity_quality=hierarchy`다. 예산, 설명, 수집 순번은
이 ID에 영향을 주지 않는다. 같은 정규 식별값은 같은 사업의 반복 수집으로 보고
첫 번째 행을 남긴다. 예산·설명이 다른 스냅샷도 별도 사업으로 보지 않는다.
최신 자료 선택이나 여러 스냅샷 병합은 이 변경의 범위 밖이다.

계층명이 부족하면 `identity_quality=row_fallback`이며, 남은 원본 필드도
식별값에 포함한다. `번호`와 이미 정규화한 제목·연도·지역·계층 필드는 제외한다.
빈 값과 필드 순서는 무시한다. 순번만 다른 반복 행은 제거하고, 같은 제목이어도
설명·예산 등 가용 정보가 다른 행은 보존한다. 이 경우 내용 보강, 예산 수정,
계층명 보완으로 ID가 바뀔 수 있다. 불완전한 자료를 잘못 합치는 것보다 중복
후보를 남기는 쪽을 택한다.

`build_policy_index()`는 중앙정부의 정규 식별값 자체를 비교한다. 여러 JSON을
합치는 RAG 로더는 새 ID로 중복을 제거한다. 모든 가용 필드가 똑같은 별개 사업은
현재 데이터만으로 구분할 수 없다. 실제 운영 데이터의 영향 건수는 조사하지 않았다.

## 호환성

- 지방정부는 기존 16자리 ID와 중복 제거 기준을 유지한다 (`id_version=1`).
- 중앙정부는 모두 v2 ID로 바뀐다 (`id_version=2`).
- `legacy_id`는 기존 알고리즘의 ID이며 추적용이다. 서로 다른 v2 ID가 같은
  legacy ID를 가질 수 있으므로 유일 키, 자동 별칭, 중복 제거 키로 쓰면 안 된다.
- ID 메타데이터는 검색 JSON과 RAG payload에 유지한다. 메타데이터가 없는 과거
  JSON도 읽지만 자동 변환하지 않는다. 과거에 누락된 행은 복구되지 않는다.
- 임베딩 배치 `custom_id`, 결과 매칭, Qdrant UUID는 새 ID에 연동된다. 기존
  배치 결과를 새 ID에 그대로 연결할 수 없다. 중앙정부 임베딩 본문에도 회계명·
  프로그램명·단위사업명이 추가되므로 기존 벡터를 무조건 재사용해서는 안 된다.

## 수동 전환 절차 (이 PR에서 실행하지 않음)

1. 원본 수집 파일, 기존 JSON, 임베딩 결과, 컬렉션 설정을 보존한다. 이미 중복
   제거된 JSON만으로 누락 복구는 불가능하다. 보존된 전체 원본이 없으면 별도
   승인된 재수집이 필요하다.
2. 전체 중앙정부 원본 행을 `export_policy_index(rows, output_path,
   source="central", ...)`에 넣어 **별도 출력 디렉터리**에 JSON을 다시 만든다.
   기본 연도·지역은 기존 수집 설정과 일치시킨다. 지방정부 JSON은 그대로 사용할
   수 있다. 구버전과 신버전 중앙정부 JSON을 같은 입력 glob에 섞지 않는다.
3. 원본 행 수, indexed/skipped, v2 ID 유일성, `row_fallback` 건수, legacy ID별
   v2 ID 개수를 비교하고 다대일 충돌 후보를 표본 검토한다. skipped에는 잘못된
   행과 반복 행이 함께 집계된다. 이 수치만으로 실제 피해 건수를 단정하지 않는다.
4. 새 JSON만 대상으로 `prepare-batch`를 실행하고, 별도 승인 후 임베딩을 새로
   생성한다. 이는 유료 외부 작업이다. 이전 배치 출력은 새 배치와 섞지 않는다.
5. 별도 승인 후 명시적으로 **새 컬렉션 이름**(예: `policy_cases_v2`)을 지정하여
   색인한다. 기존 `policy_cases_v1`에 단순 upsert하면 과거 ID 포인트가 남아
   중복 검색될 수 있다. 지방정부도 새 컬렉션으로 함께 색인하여 검색 범위를 유지한다.
6. 새 컬렉션의 사업 수, 부처별 동명 사업 검색, 지방정부 검색을 검증한 뒤 소비자
   설정을 전환한다. 이전 컬렉션은 롤백용으로 보존하고 삭제는 별도로 결정한다.
   이 PR은 기본 컬렉션이나 운영 연결 설정을 바꾸지 않는다.

외부 서비스 없이 회귀 테스트:

```bash
python3 -m unittest discover -s tests -p 'test_policy*.py' -v
```

테스트는 가상 사업, 임시 JSON/JSONL, 가상 임베딩 응답만 사용한다. 실제 열린재정,
OpenAI, Qdrant, NAS를 호출하지 않는다.
