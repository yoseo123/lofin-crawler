# 대량 수집 중단 복구와 재개

청크 저장(`limit > chunk-size > 0`)에서는 각 행을 로컬 SQLite 기록에 먼저 커밋합니다. Markdown·XLSX·검색 JSON과 manifest는 이 기록에서 생성하는 출력입니다. 단일 파일 CLI 동작과 기존 callback 인자는 유지합니다. 외부 서비스나 새 Python 패키지는 필요하지 않습니다.

## 실행과 재개

새 실행은 기존처럼 출력 경로에 타임스탬프를 붙입니다. 시작할 때 표시하는 **실제 출력 경로**를 보관하세요.

```bash
python crawl_lofin.py --source local --year 2026-01-01 --region 서울 \
  --keyword 인구 --limit 500000 --chunk-size 10000 --format both \
  --output "2026_population.md"
```

예를 들어 출력 경로가 `2026_population_20261104_170000.md`이면, 중단 후 같은 조건과 **그 경로**를 지정합니다. 아래 경로의 시각은 예시입니다.

```bash
python crawl_lofin.py --source local --year 2026-01-01 --region 서울 \
  --keyword 인구 --limit 500000 --chunk-size 10000 --format both \
  --output "2026_population_20261104_170000.md" --resume
```

중앙정부도 같은 방식으로 `--source central --year 2026`을 사용합니다. 현재 연도 허용 범위와 중앙정부 목록 추출 범위는 변경하지 않았습니다. 2027년 지원은 별도 작업입니다.

- `--resume`에서는 새 타임스탬프를 붙이지 않습니다. `--output`은 manifest 이름이 아니라 원래 출력 경로입니다.
- 출처·연도·지역·검색어·한도·청크 크기·출력 형식·상세 타임아웃이 다르면 수집 요청 전에 거부합니다. 중앙정부의 생략된 연도는 실행 시 실제 연도로 고정합니다.
- 지방정부는 전송된 검색 form도 기록하고 재개 시 대조합니다. 페이지 번호/페이지 크기는 비교에서 제외합니다. form을 얻지 못한 DOM 경로는 명시된 연도를 요구하며, 요청한 연도/지역 필터 적용 실패도 중단합니다. HTTP/DOM 경로가 달라져 검색 조건을 동일하게 확인할 수 없으면 중단합니다.
- 상세 요청 병렬 수·배치 크기·지연·화면 표시·debug 경로는 바꿀 수 있습니다.
- `--limit`은 기존 기록을 포함한 총 저장 한도이며, 재개 시 추가 할당량이 아닙니다. 목록의 앞쪽 최대 N건을 다시 확인합니다. 원격 목록 변경으로 예전 사업이 사라져도 저장 결과는 보존합니다.
- `--chunk-size 0` 또는 `limit <= chunk-size`인 단일 파일 실행은 재개 대상이 아닙니다. 기존 청크 모드의 `--json-output` 처리도 유지하며 파트별 JSON을 생성합니다.

## 저장 순서와 중단 처리

1. 행의 수집 키·원본 필드·연속 번호·SHA-256을 SQLite 트랜잭션으로 커밋합니다. `synchronous=FULL`, rollback journal을 사용합니다.
2. 청크 범위의 원본 행을 읽어 각 출력을 같은 디렉터리의 임시 파일에 완성합니다.
3. 각 임시 파일을 `fsync`한 뒤 `os.replace`로 교체합니다. POSIX에서는 상위 디렉터리도 `fsync`합니다.
4. 모든 출력이 완성된 뒤 파일명·행 범위·건수·파일별 SHA-256을 청크 기록으로 커밋합니다.
5. manifest를 같은 방식으로 교체합니다. 시작 시와 매 청크 커밋 후 기록하며 정상 종료할 때만 `complete=true`가 됩니다.

여러 파일 전체를 하나의 파일시스템 연산으로 바꾸는 것은 아닙니다. **청크 기록과 manifest를 공개 완료 기준**으로 사용합니다. 중간에 끊긴 파일 묶음은 재개 시 기록에서 다시 생성합니다. 소비자는 manifest에 나열된 파일과 SHA-256을 확인해야 합니다.

manifest의 `total_count`는 출력까지 완료된 행 수입니다. `durable_count`는 그 manifest를 작성할 때 건별 기록에 커밋된 행 수이며, 다음 manifest 갱신 전에는 실제 건별 기록보다 작을 수 있습니다. 복구 시 실제 행 수는 SQLite에서 확인합니다.

- 일반 예외와 Ctrl+C: `complete=false`로 잔여 출력을 시도하고 핸들을 해제합니다. 출력 실패가 원래 수집 예외를 가리지 않습니다.
- SIGKILL/프로세스 장애: 마지막 커밋된 행까지 복구합니다. 열려 있던 SQLite 트랜잭션은 rollback됩니다. OS 잠금은 프로세스 종료와 함께 해제됩니다.
- 상세 요청이 진행 중이거나 병렬 배치의 callback에 도달하지 않은 행은 재요청합니다. 이미 callback으로 건별 커밋된 행은 청크 크기에 도달하지 않아도 복구됩니다.
- 삭제·잘림·내용 변경이 있는 출력은 SHA-256 비교로 찾아 다시 생성합니다. manifest가 없거나 손상되어도 건별 기록과 청크 기록에서 다시 만듭니다. 남은 임시 파일은 복구 입력으로 사용하지 않습니다.
- SQLite 자체 손상, 행 체크섬/순번/청크 범위 오류는 원본을 보존하고 중단합니다. 손상된 기록을 임의 초기화하거나 정상처럼 건너뛰지 않습니다.
- 같은 출력 경로의 동시 수집/복구는 OS 잠금으로 차단합니다. 잠금 파일을 수동 삭제하지 마세요.

하드웨어와 파일시스템이 동기화 요청을 지킨다는 전제입니다. 실제 NAS 전원 차단이나 저장장치 고장은 검증하지 않았습니다. 행마다 동기 커밋하므로 NAS 디스크의 지연과 추가 원본 저장 공간이 발생합니다. SQLite 잠금·동기화가 보장되는 로컬 볼륨을 사용하고 NFS/SMB 공유에 직접 실행하지 마세요.

## 중복 기준과 기존 작업의 관계

재개 키는 검색 색인의 정책 ID와 분리합니다. `src/policy_index.py`와 `src/policy_rag.py`를 수정하지 않습니다.

- 지방정부 목록에 사업 코드·자치단체 코드가 있으면 두 코드·회계연도·조회일로 구분합니다. 코드가 부족하면 목록의 이름·지역·자치단체·연도·조회일과 가용 코드를 함께 사용합니다.
- 중앙정부는 연도·소관·회계·프로그램·단위사업·세부사업명이 모두 있을 때 이 계층으로 구분합니다. 같은 이름의 다른 부처 사업을 구분하며, 예산/순번 변경은 같은 사업으로 봅니다. 계층이 부족하면 순번을 제외한 가용 원본 목록 필드를 지문화합니다. 내용 변경 시 새 키가 될 수 있습니다.
- 목록 순서는 재개 키에 포함하지 않습니다. 목록을 처음부터 확인하되 이미 저장된 키는 상세 요청 전에 건너뜁니다. DOM 이름 클릭 fallback은 공식 코드가 없으므로 상세 수집 후 번호를 제외한 전체 행이 동일한 경우에만 중복을 제거합니다.
- 같은 키는 먼저 커밋한 행을 유지합니다. 재개는 기존 사업의 최신 내용 갱신 기능이 아닙니다. 내용/예산을 새로 수집하려면 별도 실행을 사용하세요.
- 현재 수집 필드로 구분할 수 없는 완전히 동일한 별도 사업까지 구별할 수는 없습니다.
- PR #1의 중앙정부 검색 ID 충돌 수정은 별도로 유지됩니다. 이 변경만 적용한 main의 검색 JSON에는 기존 정책 ID 동작이 남습니다. 원본 건별 기록과 MD/XLSX 보존은 그 ID 중복 제거와 무관합니다.
- 같은 실행에서 서로 다른 검색 ID 체계를 섞지 않도록 `policy_index.py` 파일의 해시도 설정에 기록합니다. PR #1 등 색인 코드 변경 전 실행의 재개는 거부합니다. 그 실행은 당시 코드에서 끝내거나, 새 코드로 별도 출력을 시작하세요. 2027년 허용 범위·자동화·운영 NAS 설정은 이번 변경에 포함하지 않습니다.

## 구버전 데이터와 보관

동일한 설정 기록을 가진 이번 버전의 CLI 실행을 자동 재개합니다. 웹 UI의 청크 출력에도 안전 저장은 적용되지만, 웹 재개 버튼과 웹 실행 기록을 CLI 설정으로 변환하는 기능은 추가하지 않았습니다. 예전 manifest/출력에는 검색어와 상세 수집 키·인덱스에서 제외된 원본 행을 완전하게 복원할 정보가 없으므로 자동 변환하지 않습니다. 구버전 결과를 보존하고 다른 출력 경로로 새 실행을 시작하세요.

`*_resume.sqlite3`와 `*_manifest.json`, part 파일을 한 실행으로 함께 보관하세요. 실행 중 복사한 SQLite 파일만으로 백업을 만들지 마세요. 프로세스가 완전히 종료된 상태에서 journal 파일이 남아 있다면 삭제하지 말고 SQLite 파일과 함께 보존하세요. 수집/복구 중 파일 이름이나 경로를 옮기지 마세요. JSON/MD/XLSX만 남기고 SQLite 기록을 지우면 이 복구 기능을 사용할 수 없습니다.

## 오프라인 회귀 테스트

```bash
python3 tests/run_offline.py
```

가상 정책·임시 디렉터리·가짜 브라우저/상세 응답을 사용합니다. runner가 부모와 SIGKILL 시험용 Python 자식 프로세스의 소켓·DNS 연결을 차단하고, 다른 외부 실행 파일도 차단합니다. 차단된 시도를 코드가 예외 처리로 삼켜도 audit가 실패합니다. 실행에 실제 브라우저 설치나 대상 사이트 호출이 필요하지 않습니다. 저장소 Python 의존성은 설치되어 있어야 합니다.

검증 대상은 정상 종료, 일반 예외, Ctrl+C, SIGKILL(행 트랜잭션/출력 임시 파일/파일별 교체/청크 커밋/manifest 단계), 누락·부분 파일 손상, 기록 손상 시 중단, 중복·동명 사업·목록 재정렬, 실제 검색 조건 불일치, 동시 실행 거부와 기존 단일 파일 CLI입니다. POSIX SIGKILL 테스트는 Windows에서 skip됩니다. Windows 잠금·전원 장애와 실제 사이트 연동은 별도 환경 검증이 필요합니다.
